# 峰时段提醒

在「规则与提醒」开启「峰时段前 5 分钟提醒」。默认关闭，不会在安装时申请权限，也不会创建提醒计时器。首次开启可能需要允许应用的系统通知。

开启后可以点击「测试提醒」。它立即显示右下角的应用内提示，并尝试发出独立的系统通知，不修改实际峰时段的已发送记录。通知语言随 Harness 当前语言，时间固定使用北京时间。

v1.3.2 的正式提醒和测试提醒同时播放约 0.56 秒的轻柔两音提示。声音通过 Web Audio 在本地合成，没有音频下载或额外依赖；淡入淡出限制峰值振幅，系统通知设置 `silent: true`，避免系统音与插件音重复。实际听到的音量仍由设备与应用音量决定。

开启提醒时以及已开启状态下的普通鼠标/键盘交互会准备音频，遵循 [Web Audio 的用户交互要求](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices#autoplay_policy)。自动播放请求没有结果时 1 秒后显示提示音不可用，应用内提醒与系统通知不受影响。连续点击测试会立即停止上一声；关闭提示、关闭开关或卸载会停止播放，卸载还会关闭 AudioContext。延迟的音频启动回调不能在关闭或卸载后补响。

应用内提示可以关闭，不自动抢占输入焦点；系统通知点击后可回到应用。只有收到 Notification 的 `show` 事件才显示「系统已接收通知」；这不保证用户看到了横幅，勿扰模式仍可能抑制横幅。5 秒没有回执时显示「系统未确认通知显示」，同步或异步失败时显示发送失败，应用内提示继续保留。重复测试替换上一条提示并关闭旧系统通知，旧回调不能覆盖新的发送状态。

## 时机与生命周期

- 对下一次已核实的峰时段，在开始前 5 分钟发送；在这 5 分钟内刚开启或唤醒时，也会提醒尚未开始的峰时段。
- 周末、公共假期及未核实的峰时段不发出确定提醒。日历自动更新会重新计算截止时间。
- 应用隐藏时仍保留一个截止时间计时器；休眠唤醒后重新读取系统时间，已经开始的峰时段不补发。
- 关闭开关立即取消待发送提醒。插件卸载会取消计时器与订阅，并关闭由本插件创建的通知。
- 实际峰时段提醒和测试提醒使用同一发送流程；系统通知不可用时保留应用内提示，不关闭已启用的提醒，不清除已发送记录，因此不会每秒重复弹出。
- 应用必须保持运行；完全退出后不能提醒。系统勿扰、通知权限和宿主安装条件会影响是否显示横幅。

## 保存与去重

偏好保存在当前来源的本地存储，使用 `dsh-timeband/reminders/v1`；最近已通知的峰时段保存在 `dsh-timeband/reminder-sent/v1`。记录只包含开关和时间，不包含账户、消费或 API Key。

同来源的现代 Chrome/Electron 窗口使用 Web Locks 串行核对并保存发送记录，防止同一截止时间同时弹出多条通知。没有 Web Locks 的环境退回本地记录和相同通知 tag，此类旧环境不保证跨窗口的原子去重。桌面与 Web 来源不同，各自保存偏好与记录。

系统时间向后调整时，不重发早于已发送记录的峰时段。系统发送错误保留应用内提醒；应用内发送本身出错时才关闭提醒并恢复发送记录。无法保存偏好时不显示已成功开启，无法保存发送记录时不发送通知。

## 验证边界

时间、权限、错误及生命周期由 Node 与真实构建产物的 Chrome 测试验证。Chrome 使用受控通知替身，不代表已验证本机 Windows 的通知横幅。2026-10-04 在本机旧版 v1.3.0 复现测试按钮无页面反馈，系统横幅没有得到确认；v1.3.1 的实际桌面结果记录在兼容性文档。

桌面渲染进程通过标准 Web Notification API 创建通知，依据 [Electron 官方通知说明](https://www.electronjs.org/docs/latest/tutorial/notifications#show-notifications-in-the-renderer-process)；回执依据 [Notification show 事件](https://developer.mozilla.org/en-US/docs/Web/API/Notification/show_event)。不修改宿主的权限处理、安装注册信息或系统勿扰设置。
