# 峰时段提醒

在「规则、日历与提醒」开启「峰时段前 5 分钟提醒」。默认关闭，不会在安装时申请权限，也不会创建提醒计时器。首次开启可能需要允许应用的系统通知。

开启后可以点击「测试提醒」。它立即发出独立的测试通知，不修改实际峰时段的已发送记录。通知语言随 Harness 当前语言，时间固定使用北京时间。

## 时机与生命周期

- 对下一次已核实的峰时段，在开始前 5 分钟发送；在这 5 分钟内刚开启或唤醒时，也会提醒尚未开始的峰时段。
- 周末、公共假期及未核实的峰时段不发出确定提醒。导入或恢复日历会重新计算截止时间。
- 应用隐藏时仍保留一个截止时间计时器；休眠唤醒后重新读取系统时间，已经开始的峰时段不补发。
- 关闭开关立即取消待发送提醒。插件卸载会取消计时器与订阅，并关闭由本插件创建的通知。
- 应用必须保持运行；完全退出后不能提醒。系统勿扰、通知权限和宿主安装条件会影响是否显示横幅。

## 保存与去重

偏好保存在当前来源的本地存储，使用 `dsh-timeband/reminders/v1`；最近已通知的峰时段保存在 `dsh-timeband/reminder-sent/v1`。记录只包含开关和时间，不包含账户、消费或 API Key。

同来源的现代 Chrome/Electron 窗口使用 Web Locks 串行核对并保存发送记录，防止同一截止时间同时弹出多条通知。没有 Web Locks 的环境退回本地记录和相同通知 tag，此类旧环境不保证跨窗口的原子去重。桌面与 Web 来源不同，各自保存偏好与记录。

系统时间向后调整时，不重发早于已发送记录的峰时段。发送错误会关闭提醒，防止每秒重试；修复权限后可手动重新开启。无法保存偏好时不显示已成功开启，无法保存发送记录时不发送通知。

## 验证边界

时间、权限、错误及生命周期由 Node 与真实构建产物的 Chrome 测试验证。Chrome 使用受控通知替身，不代表已验证本机 Windows 的通知横幅。新版桌面安装后应点击「测试提醒」检查实际展示。

桌面渲染进程通过标准 Web Notification API 创建通知，依据 [Electron 官方通知说明](https://www.electronjs.org/docs/latest/tutorial/notifications#show-notifications-in-the-renderer-process)。不修改宿主的权限处理或安装注册信息。
