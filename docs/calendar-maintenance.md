# 日历维护

当前正式数据只有 2026 年。新年份必须以国务院办公厅公告或政府网站转载为依据，不能从工作日日历推导峰谷计费日；周末包括调休上班日，仍按谷时段。

## 自动更新

v1.3.0 不再提供手动导入或恢复。当前连续覆盖日历到期前 30 天，插件从 `https://raw.githubusercontent.com/NateScarlet/holiday-cn/master/{年份}.json` 下载下一年日历；打开应用时缺少本年度数据则立即获取本年度。该开源数据源自动抓取国务院公告，不要求本插件的用户或维护者每年上传文件。新文件未发布、为空占位或下载失败，每 24 小时自动重试。网络恢复后重试失败请求，应用退出后暂停，重新打开继续检查。

有效远程文件必须有正确的 `year`、HTTPS 政府公告 `papers` 和完整的 `days` 条目；验证真实日期、唯一日期、布尔 `isOffDay` 及节日名称，下载不超过 64 KB 且 10 秒内完成。没有公告且日期为空的年度占位文件不会被接受为覆盖。`isOffDay: true` 的日期转为连续假期间隔，`false` 不改变周末计费；涉及此前 12 月的部分安排只合并到已有完整覆盖的年份。自动缓存的 `verifiedOn` 记录取得并校验数据的北京时间日期，不表示重新人工核对全部公告。

文件合并进本地缓存，保留已有年份和更新的核对结果。旧版导入缓存会与内置日历合并，不再要求用户点「恢复内置」。没有对应年度官方数据时仍显示待核实，不用普通工作日历预测计费假期。

日历保存键保持 `dsh-timeband/calendar/v1`，每日检查记录使用 `dsh-timeband/calendar-check/v1`。Web 与桌面来源不同，各自自动更新、保存和去重。

## 内置与缓存格式

参考 [2026 年完整示例](../calendars/2026.json)。文件为 UTF-8 JSON，最大 64 KB，包含：

| 字段 | 要求 |
|---|---|
| `schemaVersion` | 固定为 `1` |
| `years` | 已核对的完整年份，升序、不重复，每年必须有假期条目 |
| `verifiedOn` | 人工核对日期，格式 `YYYY-MM-DD` |
| `source` | HTTPS 政府网站公告地址，域名为 `gov.cn` 或其子域 |
| `holidays` | 放假日期闭区间 `[起始日, 结束日]`，按起始日排序、不重叠，每段限同一年 |

跨年放假应拆成分别属于两个年份的区间。列入 `years` 就表示已核对该年的全部放假安排，不仅是部分节日。地址校验不能证明内容正确，维护者需人工核对原公告。

## 发布新日历

1. 查阅当年政府公告，整理完整放假区间，保留已有年份及其日期。
2. 在 `calendars/` 新增以年份命名的汇总文件，更新核对日期与本次公告来源；在此文档保留历年来源链接。
3. 年度文件用于更新随包提供的离线默认数据；让 `src/calendar.ts` 导入新的完整汇总文件。自动更新只读取 holiday-cn 公告数据，不读取本项目主分支的年度 JSON。
4. 运行 `npm run check`，特别核对第一天、最后一天、调休周末及跨年倒计时。
5. 默认内置数据更新时发布插件新版本。在线用户会自动获得公开源的年度更新，无需等待本项目发布年度文件或 npm 新版；仍建议维护内置数据，便于新安装后离线使用。
